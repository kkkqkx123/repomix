# Repomix 技术架构设计

## 整体架构

Repomix 采用分层架构设计，将不同的功能模块清晰地分离，确保系统的可维护性、可扩展性和可测试性。

└─────────────────────────┬───────────────────────────────────┘
                          │
┌─────────────────────────┴───────────────────────────────────┐

## 核心模块架构

### 1. CLI 层 (`src/cli/`)

**职责**: 用户界面和命令处理

**主要组件**:
- **Actions**: 命令动作处理器（默认、初始化、远程、MCP、版本）
- **Options**: 命令行选项解析和验证
- **Reporters**: 进度报告和状态输出
- **Types**: CLI 相关的类型定义

**设计特点**:
- 语义化命令映射，提供智能建议
- 分组选项管理，提高用户体验
- 详细的错误处理和用户反馈

### 2. 核心处理层 (`src/core/`)

#### 2.1 打包引擎 (`packager.ts`)
**职责**: 主要的打包逻辑协调器

**核心流程**:
```
文件搜索 → 文件收集 → 安全检查 → 文件处理 → 输出生成 → 度量计算
```

**设计模式**:
- 依赖注入模式，提高可测试性
- 进度回调机制，实时反馈
- 内存使用监控，优化性能

#### 2.2 文件处理系统 (`file/`)
**职责**: 文件发现、过滤和处理

**子模块**:
- **File Collect**: 文件收集和模式匹配
- **File Process**: 文件内容处理（注释移除、压缩等）
- **File Search**: 递归文件搜索
- **Path Sort**: 文件路径排序和优化
- **Path Flattener**: 路径扁平化处理

**设计特点**:
- 流式处理大文件
- 并行处理提高效率
- 智能过滤规则引擎

#### 2.3 输出生成系统 (`output/`)
**职责**: 生成多种格式的输出

**支持格式**:
- XML: 结构化数据，适合 AI 处理
- Markdown: 可读性强的文档格式
- JSON: 机器友好的数据格式
- Plain: 纯文本格式

**设计特点**:
- 模板化输出生成
- 可配置的输出选项
- 内容压缩和优化

#### 2.4 安全检查系统 (`security/`)
**职责**: 检测和处理敏感信息

**检测内容**:
- API 密钥和令牌
- 密码和凭据
- 私钥和证书
- 敏感配置信息

**设计特点**:
- 可配置的安全规则
- 多层次安全检查
- 详细的检测报告

#### 2.5 Git 集成 (`git/`)
**职责**: Git 仓库信息提取

**功能模块**:
- **Git Diff**: 获取工作区和暂存区变更
- **Git Log**: 获取提交历史和统计
- **Git Ignore**: 解析 .gitignore 规则

**设计特点**:
- 支持多种 Git 操作
- 增量数据处理
- 与文件处理系统集成

### 3. 基础设施层 (`src/shared/` 等)

#### 3.1 配置管理 (`config/`)
**职责**: 配置加载和验证

**功能**:
- 配置文件解析（JSON 格式）
- 命令行参数合并
- 默认配置管理
- 配置验证和类型安全

#### 3.2 共享工具 (`shared/`)
**职责**: 通用工具和功能

**工具模块**:
- **Logger**: 日志管理和格式化
- **Error Handling**: 统一错误处理
- **Memory Utils**: 内存使用监控
- **Pattern Utils**: 模式匹配工具
- **Process Concurrency**: 并发处理控制

#### 3.3 MCP 服务器 (`mcp/`)
**职责**: AI 工具集成

**功能**:
- Model Context Protocol 服务器
- 工具注册和管理
- 远程仓库支持
- 文件系统操作

## 数据流架构

### 1. 文件处理数据流
```
输入目录 → 文件搜索 → 模式过滤 → 文件收集 → 内容处理 → 输出生成
```

### 2. Git 集成数据流
```
Git 仓库 → Diff 获取 → Log 获取 → 历史分析 → 元数据集成
```

### 3. 安全检查数据流
```
文件内容 → 敏感信息扫描 → 安全规则匹配 → 检测报告生成
```

### 4. 输出生成数据流
```
处理后的文件 → 格式选择 → 模板渲染 → 内容优化 → 最终输出
```
